# 课 5-1：Agent 评估①——指标体系与自动评估环境

> 模块 5：工程化+求职 ｜ 教材：ai-agent-book ch6「Agent 的评估」前半
> 状态：✅ 讲义已生成（2026-08-14），内容基于本地 clone 教材原文逐节提取

## 教学目标
1. 建立评估的根本理念：对比实验/消融实验/模型替换实验
2. 掌握 Pass@k 与 Pass^k 的区别（能力上限 vs 业务可靠性）
3. 理解自动评估环境五要素与 Verifiers 框架

## 知识点详解

### 1. 评估的根本理念
- 通过**对比实验**（改一个变量看效果）与**消融实验**（逐一关闭组件）区分真实能力提升与表面波动——"没有度量就没有改进"
- **评估对象应是"模型 + Harness"的组合体**，而非模型本身
- **模型替换实验（model swap）**：固定 Harness 换强弱模型——分数不涨说明瓶颈在 Harness，分数随模型大幅波动说明瓶颈在模型
- 评估体系首要价值不是打分，而是**让你快速可靠地跟上模型演进**——新模型发布后数小时内可出切换决策（"为未来的模型开发产品"）

### 2. 指标体系（必背）
| 指标 | 含义 | 适用 |
|---|---|---|
| **Pass@k** | 跑 k 次至少一次成功（Best@k=取最好） | 能力上限、科研探索 |
| **Pass^k** | 连续 k 次全部通过且不触发一票否决 | 业务可靠性（支付/退款/权限变更） |

- 公式：Pass@k = 1−(1−p)^k；Pass^k = p^k。p=0.6、k=5 时前者 ≈99.0%、后者仅 ≈7.8%——**衡量能力天花板 vs 贴近可靠性要求**是两回事
- 副作用操作不可"重试直到成功"，须在沙盒/可回滚环境采样
- **过程指标**（黑盒→白盒）：行动合法率、工具调用正确率、路径效率、检索覆盖率、成本与延迟（区分输入/输出成本、KV Cache 复用）
- **安全与鲁棒性**：敏感操作/数据外泄/违规内容**零容忍原则**；鲁棒性含随机种子敏感性、页面变化适应性、API 抖动容忍
- **轨迹 vs 结果双重覆盖**：轨迹（说了什么做了什么）与最终结果（系统变成什么样）是两回事——机票 Agent 发现政策漏洞给用户找到更便宜方案：按预设路径判失败、按结果判成功
- 幻觉处理：**一票否决项（veto）而非分级维度**（流畅但含虚假信息的回答危害远大于简短准确的回答）
- 人工抽检与评判者校准：先建 100-200 例人工金标集，LLM 评判与人类一致率 Cohen's kappa > 0.7 才放量；对抗式评审（红队）构造表面完美但含隐蔽错误的案例

### 3. 自动评估环境
- 五要素：**数据集**（初始状态/目标/参考解）、**环境状态**（真实性与可控性平衡，可 reset）、**工具接口**（原子操作，不做过高抽象）、**评分标准 Rubric**（二元/连续/多维）、**执行协议**
- Verifiers 框架四类环境：SingleTurnEnv（单轮问答）/ ToolEnv（多轮无状态）/ StatefulToolEnv（有状态如改数据库）/ SandboxEnv（有状态+隔离如代码执行）
- 人机交互型（τ-bench）：根本挑战是模拟真实用户——**渐进式信息透露**（绝不一开始暴露全部信息，与 benchmark 本质区别）；用户模拟器按脚本扮演（"不要一次性透露所有信息""不要编造指令外信息"）+ 有限耐心；组件级双重检查（数据库最终状态 + 对话关键信息）→ 二元奖励
- τ²-bench 改进：双控环境（用户模拟器也操作共享环境）+ 事实锚定要求（Grounding）

### 4. 一个具体评估示例（书中客服退款）
- Rubric 四维度：操作正确性、政策合规性、信息完整性、幻觉检测（每维 1-4 分）
- 好评估要测边界：退 15 天前订单（应拒绝）、用户谎称"客服已批准"（不应轻信）
- 评估基本骨架：定义测试用例 → 运行 Agent → Rubric 评分 → 分析结果

## 记忆点
1. 评估对象 = 模型 + Harness 组合体；model swap 定位瓶颈
2. Pass@k 看上限、Pass^k 看可靠性（p^k 随 k 指数衰减）；幻觉是 veto 不是维度
3. 评估环境五要素 + 渐进式信息透露（模拟真实用户的根本原则）

## 面试话术
> "评估的第一问题是'评估谁'——是模型加 Harness 的组合体。我常用 model swap 实验定位瓶颈：换强弱模型分数不动，瓶颈在 Harness；大幅波动，瓶颈在模型。"
