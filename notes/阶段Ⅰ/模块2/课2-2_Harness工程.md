## 教学目标
1. 掌握生产形态方程：**Agent = Model + Harness**，Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正
2. 理解 Harness 五要素（Context/Tools/Constrain/Verify/Correct）及各自原则
3. 区分工作流与自主 Agent 两种编排模式，掌握"从简单到复杂"原则
4. 认识护栏三分层（输入侧/执行侧/输出侧）与人在回路（HITL）

## 知识点详解

### 1. 生产形态方程
```
Agent = Model + Harness
Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正
```
- Harness 隐喻：马具不是限制马的奔跑，而是把力量引导到正确方向；**模型越强大，Harness 就越关键**（自主决策空间越大，出错影响面越大）
- 精确边界：Harness 是 **Agent 边界内、模型之外**的运行与治理层；沙箱内的文件/进程、外部数据库属于 Environment

### 2. Harness 五要素（必背）
| 要素 | 职责 | 核心原则 |
|---|---|---|
| Context | 提供感知信息 | 信息要充分 |
| Tools | 提供观察与行动手段 | 接口要清晰 |
| **Constrain** | 设定行为边界 | **故障安全默认值：所有能力默认关闭，必须显式开放** |
| **Verify** | 自动判断结果对错 | **只查结构化数据，不看模型自由文本**（防提示注入操纵） |
| **Correct** | 发现错误自动修正/回退 | 静默重试；连续失败熔断回退人工 |

- 行业判断：早期框架关注上下文与工具（**能做事**），生产级系统重心转向约束、验证与纠正（**可靠地做事**）
- 实例：Claude Code 的 Harness 绝大部分代码是约束/验证/纠正（含熔断器 Circuit Breaker）

### 3. 工程范式演进（五层包含关系）
提示工程 → 上下文工程 → **Harness 工程** → Loop 工程（跨轮次持续自主运转）→ Graph 工程（2026-07 起：节点+类型化边+可检查点状态）
- 数据佐证（书中）：LangChain 在 Terminal Bench 2.0 上 Coding Agent 成绩从 52.8% → 66.5%（前 5 名），**改变的不是模型而是 Harness**

### 4. 构建有效 Agent 的三条核心原则（Anthropic 经验）
1. **保持简单**：直接 API 调用优于复杂框架；每多一层抽象都是调试新盲区
2. **保持透明**：显示规划步骤、执行日志、决策轨迹（调试+用户信任）
3. **设计好工具接口（ACI）**：从 Agent 视角设计接口；用设计让错误无法发生（防呆 Poka-yoke：SIM 卡缺角、微波炉门未关不加热）

### 5. 编排模式：工作流 vs 自主 Agent
- **从简单到复杂**：单次 LLM 调用（够用就别上 Agent）→ 工作流（可清晰分解为固定子任务）→ 自主 Agent（需要动态决策）
- **工作流**：预定义代码路径，LLM 只在节点内部生成。优势=严格流程控制（付款前不能预订由代码强制）+ 攻击面限制在单节点；局限=缺乏变通
- **自主 Agent**：执行路径由环境反馈实时决定（就是 ReAct 循环）；必须有明确停止条件（任务完成/最大迭代/不可恢复错误）；风险=成本与复合错误
- 混合使用：关键合规流程用工作流，灵活决策用自主（如 n8n 可视化框架）

### 6. 护栏与人在回路
- 护栏三分层：**输入侧**（相关性分类器/安全分类器【越狱 vs 提示注入的区别：操纵者是谁】/内容审核/规则过滤）→ **执行侧**（工具风险评级）→ **输出侧**（PII 过滤器/输出验证）
- 护栏评估不能只测"该拒绝的拦没拦"，还要测"该放行的过没过"（误拒绝问题）
- 人在回路两种触发：超过失败阈值、高风险操作（大额退款/付款）

## 记忆点
1. Harness 五要素：Context/Tools + **Constrain/Verify/Correct**（后三者是生产级重心）
2. 三原则：简单、透明、接口对 Agent 友好（ACI）
3. 编排顺序：单次调用 → 工作流 → 自主 Agent；护栏=分层防线，HITL=关键保护

## 面试话术
