## 教学目标
1. 理解 Agent 状态栏的机制：把隐式状态提炼为显式知识
2. 掌握状态栏的三种构成与两种实现（每轮替换 vs 持久追加）
3. 理解上下文压缩的两个动机与"上下文腐化"概念

## 知识点详解

### 1. 状态栏：元信息注入机制
- 定义：Agent 框架把动态信息（任务进度、环境变化、工具调用计数）整理成结构化摘要注入上下文
- 类比：手机屏幕顶部的时间/电量/信号——不是主界面，但瞥一眼掌握状态
- **理论基础：上下文学习更像检索而非推理**——模型擅长从已有内容中查找信息，不擅长主动归纳统计（单次前向传播中）
  - 书中例子："打了 3 次电话"的知识以原始通话记录形式散落各处，模型每次决策都重新数——解法：工具结果中直接注入"本次是第 3 次呼叫该商家"

### 2. 状态栏的有效性（书中转引 Li & Shi, *Distill, Don't Retrieve*, 2026）
- ①弱模型补回来的是**准确率**（最弱模型 +40~54 个百分点，2B 小模型追平无状态栏的前沿大模型）
- ②强模型省下来的是**效率**（思考量/延迟/花费各降约一个数量级）
- ③带状态栏后每次查询思考量基本恒定——模型只是"瞥一眼"那几格状态

### 3. 三条实操经验（必背）
1. **状态栏要用代码维护，别拿大模型维护**——让 LLM 一次性读完整历史吐统计结果反而出错；能用代码算就用代码算；实在要用 LLM 也逐条抽取再代码汇总
2. **不要删掉原始上下文**——状态栏是对原始上下文的有损投影（只提前算预想会被问的维度）；够用时可删原始记录省 token，但一旦被问未覆盖维度，只留状态栏准确率断崖式崩塌
3. **把状态栏准确率当一线生产指标**——模型几乎无条件相信状态栏；状态栏写错，错误原样传进答案（状态栏投毒风险）

### 4. 状态栏三种构成
- **任务规划**：TODO 列表放轨迹末尾持续提醒进展（启用 TODO 的 Agent 平均 15 次迭代 vs 禁用 21 次）
- **事件侧信道信息**：精确时间、地理位置、距上次回复的间隔
- **环境当前状态摘要**：系统时间、工作目录、异常操作提醒（"该工具已被重复调用 N 次"）
- 五种好用的技术（实验 2-9）：时间戳跟踪（放用户消息/工具响应前缀，**不放系统提示词**）、工具调用计数器（隐式成本感知）、TODO 列表管理、详细错误信息（错误场景成功率 60%→95%）、系统状态感知

### 5. 状态栏的位置与两种实现
- 位置：API 层面作为一条 **user 角色消息**插入上下文**末尾**（修改 system 会破坏前缀缓存）——追加而非修改
- 实现一（每轮替换）：移除旧状态、追加新状态——只有一份永远最新；代价=旧状态位置之后的缓存失效（通常只覆盖一轮，前缀仍可复用）
- 实现二（持久追加，Claude Code `<system-reminder>` 采用）：只追加不改——缓存完全友好；代价=陈旧状态累积占用 token，要求模型自己忽略过时旧状态
- 取舍：状态小/更新少/会话短 → 实现二；状态大/更新频繁/轨迹长 → 实现一

### 6. 上下文压缩策略
- **两个动机**：①长度与成本约束（窗口撑满）；②**提升思考质量——总结后的知识比原始形式更利于模型使用**（更易被忽视）
- **上下文腐化（Context Rot）**：窗口没满但 Agent 找不到关键信息、反复纠结已解决的问题——注意力被无关内容稀释，决策质量悄然下降
- 设计原则：**不要让模型被动地在海量信息中检索，而要主动为模型提供经过提炼的结构化知识**
- 压缩与 KV Cache 的关系：压缩发生在**两次 API 调用之间**由框架预处理；对象是对话历史中的 tool results（替换位置之后缓存失效，之前的保留）——在上下文接近阈值时**批量压缩**而非每轮都压
- **隔离优于压缩**：子 Agent 上下文隔离（把长任务分给子 Agent，各自上下文独立）
- 生产级分层压缩机制：保留关键信息类型（decisions、constraints、failures、citations）批量压缩旧工具输出

## 记忆点
1. 状态栏 = 把分散的隐式状态提炼为显式知识，注入上下文末尾
2. 三经验：代码维护 / 不删原始上下文 / 准确率当生产指标
3. 压缩两动机：省 token + 提升思考质量；腐化≠溢出；隔离优于压缩

## 面试话术
> "长上下文不等于好上下文——上下文腐化比溢出更隐蔽。生产级系统的做法是状态栏提炼 + 分层压缩 + 子 Agent 隔离三件套，核心思想是主动蒸馏而非被动检索。"
