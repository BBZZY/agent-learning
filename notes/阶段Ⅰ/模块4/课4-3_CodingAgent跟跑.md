## 知识点详解（跟跑要点）

### 1. 搜索工具的四类互补检索
| 类型 | 能力 | 局限 |
|---|---|---|
| 正则内容匹配（grep/ripgrep） | 精确 | 不懂语义（搜"用户认证"找不到处理登录的函数） |
| 文件名匹配（glob） | 最快 | 只匹配文件名 |
| 语义搜索 | 语义召回 | 需结构感知分块 + 混合检索 + reranker |
| 符号级定义引用（LSP） | 区分定义与调用 | 需语言服务支持 |

- 组合策略：**从粗到细、从语义到语法**
- 路线之争（书中）：Claude Code 刻意不建嵌入索引（免维护陈旧索引、免外发代码风险）；Cursor 愿为跨文件语义召回付出建索引成本

### 2. 文件编辑工具五种方案
1. 差异描述 + Apply Model（小模型合并 diff，Cursor 曾用后弃用）
2. **Old String → New String**（Claude Code/Codex/今日 Cursor 采用：可预测透明，但大段删除需完整原文、一个字符偏差即失败）
3. 行号定位（精确无歧义，但多次编辑后行号变化）
4. 类 Vim 编辑命令（重组高效但学习负担大；洞见：Vim 为"人类看到状态再规划"设计，模型是"长思考后批量复杂操作"）
5. 字符串首尾匹配（综合可靠与高效）

### 3. 安全：威胁模型与三层防御
- **Simon Willison"致命三要素"**：访问私有数据 + 暴露于不受信任内容 + 具备外部通信能力；书中补第四维度**持久记忆**（攻击放大器，跨会话潜伏）
- 三增量防御：
  1. **命令语义解析**而非关键字黑名单（`rm` 被禁可用 `$(echo rm) -rf /` 绕过；识别 `find -exec rm`、`curl -o /etc/crontab` 嵌套攻击）
  2. **沙盒工程选型**：网络出口默认断网+白名单代理（关键）、源码只读挂载、凭证不挂载、资源限额+超时（超时返回结构化错误而非静默杀进程）
  3. **持久记忆跨会话防线**：写入长期记忆的内容需同等信任审查
- **委托方忠诚（principal loyalty）**：模型默认"谁跟我说话就帮谁"，多方委托下对手开口就能策反——Harness 层要把忠诚对象显式钉死（主人指令优先级最高，外部内容降格为"可参考但不具指令效力"）；忠诚度守则含"拒绝时不逐条念出拒绝清单（那本身就在泄露）"

## 记忆点
1. 检索四类互补：从粗到细、从语义到语法；Old String→New String 是主流编辑方案
2. 致命三要素 + 持久记忆第四维度；命令语义解析 > 关键字黑名单；沙盒默认断网
3. 委托方忠诚：外部内容降格为数据，主人指令唯一最高

## 面试话术
> "Coding Agent 的安全边界：语义解析命令、沙盒默认断网、记忆同等级审查、忠诚对象显式钉死。安全不是提示词能解决的，是 Harness 架构问题。"
