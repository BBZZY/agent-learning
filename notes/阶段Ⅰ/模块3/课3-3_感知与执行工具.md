## 教学目标
1. 掌握感知工具的关键设计（分页/显式截断/只读红利）与多模态三路径
2. 掌握执行工具的四层安全机制 + 提议者-审核者 + Sidecar 机制
3. 理解幂等性与"预检-确认"两段式

## 知识点详解

### 1. 感知工具设计要点
- 核心挑战：返回信息量远超 Agent 处理能力（搜索数万字符、PDF 上百页）→ 工具层集成上下文感知压缩（超阈值基于当前查询意图自动压缩）
- **搜索类**：返回结构化候选列表（标题/位置/摘要片段）而非全文拼接；分页或 cursor 参数，注明总数
- **读取类**：offset/limit 按需读取；**截断必须显式可见**（"已显示第 1-200 行，共 5000 行"）——静默截断危险：Agent 误以为看到全部内容，基于不完整信息做错误判断
- **只读性红利**：不改变世界 → 结果可安全缓存、多感知调用可放心并行

### 2. 多模态感知三路径
1. **原生多模态处理**：专门编码器映射到统一语义空间（Qwen-VL/LLaVA 用 ViT 把图像切成 Patches 序列化）；能力上限最高（图表/布局理解最佳），token 消耗大
2. **提取为文本**：OCR/转录转纯文本（适合 GLM 5.2、DeepSeek V4 Flash 等无原生视觉的强模型）；纯文本文档成本最低，但版式/图表信息丢失
3. **工具化多模态分析**：analyze_image/analyze_pdf 工具（内部可用多模态模型，不需强 Agent 能力）；交互式场景灵活，成本低
- 选择：按内容类型——纯文字用提取、布局敏感（UI/表格/设计稿）保留图像

### 3. 执行工具的安全：多层防护
- 核心挑战：错误代价极高（误删不可恢复、误调用真实财务损失）
- **第一层 输入验证**：路径遍历攻击（`../../etc/passwd`）、命令注入（分号/管道拼接）、参数类型格式；关键是**快速失败**——发现异常立即拒绝，不尝试"智能"修正
- **第二层 权限控制**：文件操作限工作目录；命令黑名单（rm -rf /、dd if=/dev/zero）；黑名单只是最基础层（变形命令可绕过，需语义解析）

### 4. 提议者-审核者（Proposer-Reviewer）
- 思想：独立第二视角检验第一视角产出（银行经办+审核双签）
- **事前审批**三个要点：
  - 模型选择：**不同家族但能力相似**（认知多样性；同家族训练数据相似易同错；能力悬殊审查不可靠）
  - 提示词：底层规则完全一致但关注点差异化（提议者=行动导向，审核者=风险控制）
  - 审批失败处理：拒绝理由作为工具调用结果加入轨迹——从提议模型视角看就是一次"工具调用失败返回修正建议"
- **事后验证**：要诀在**模态切换**——不在同一模态重读（生成文档后渲染为视觉输出检查排版；改配置后在沙盒实际运行验证）
- 优化：风险分级审批（高风险总审批/低风险直接执行）、人类监督升级

### 5. Sidecar 机制（重点）
- 定义：主模型决定执行工具调用时，独立轻量级 LLM 同步判断"这个调用是否安全"（微服务边车模式）
- 关键设计：
  - **与流式输出并行**：主模型继续生成时审查同步开始，危险操作门控（放行前不真正执行）
  - **输入隔离**：Sidecar 只读结构化字段 `{tool: "bash", command: "rm -rf /tmp/data"}` 而非主模型上下文——否则提示注入可能被误判为合理理由
  - 轻量模型足以胜任（审查的是简单分类问题"这条命令是否危险"，不是开放式思考）
- 拒绝熔断器：连续多次拒绝→回退请求用户手动判断（Harness"纠正"的典型实例）
- 安全检查"隐形"：界面先显示进度，后台同步安全检查——安全不以牺牲体验为代价
- Sidecar 另一应用：并行构造上下文（筛选用户记忆、为长工具输出生成摘要）

### 6. 自动验证、幂等性与隔离
- **执行-验证-反馈闭环**：write_file 写代码后自动跑 linter，错误作为结构化列表返回——Agent 下一轮就带着具体错误修正
- **幂等性**：同一操作执行一次和多次对外部影响完全相同，才可安全重试。手段：唯一标识服务端去重 + 先查询后变更
- **不可幂等操作**（发邮件/拨打电话/转账）用**"预检-确认"两段式**：第一段校验预演返回确认令牌，第二段凭令牌执行；执行失败不盲目重发，交回上层重新预检
- **隔离强度三级**：进程级（本地同用户权限，Claude Code/Codex/OpenClaw 默认）< 容器（Docker 独立文件系统，共享内核）< microVM/虚拟机（Firecracker，独立内核，最强）
- **澄清：venv 不是沙盒**——只隔离包依赖，对文件系统/网络/进程无安全约束

## 记忆点
1. 感知工具：显式截断 > 静默截断；只读红利=缓存+并行
2. 执行安全：输入验证→权限控制→Proposer-Reviewer（异源同能）→Sidecar（结构化输入隔离）
3. 幂等才可重试；不可幂等用预检-确认两段式；venv≠沙盒

## 面试话术
> "执行工具的安全是分层体系：快速失败的输入验证、最小权限、异源互审（Proposer-Reviewer）、Sidecar 结构化门控。两个关键设计哲学：审查者只读结构化字段防注入，验证要切换模态避开同一盲区。"
